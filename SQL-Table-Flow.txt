System Overview: Ley Billing and Collection System

This system is designed to manage the entire billing lifecycle for a business, from customer creation to invoicing and payment collection. It provides a structured way to track receivables and maintain a clear audit trail.

---

**Logical Process Flow and Table Relationships:**

The system's data flow is centered around customers, invoices, and payments.

**1. `tbl_customers`**

*   **Purpose:** This is the master table for all clients. Every transaction starts with a customer.
*   **Process Flow:**
    *   A new client is registered in the system and a record is created in `tbl_customers`.
    *   This table holds essential details like name, business name, address, and contact information.
    *   The `id` from this table is used as a foreign key in invoice and payment tables.

**2. `tbl_charge_invoices` & `tbl_charge_invoice_items`**

*   **Purpose:** These tables represent a formal bill for services or products. `tbl_charge_invoices` is the header, and `tbl_charge_invoice_items` contains the individual line items.
*   **Process Flow:**
    *   A user creates a new charge invoice and links it to a customer via `customer_id`.
    *   The invoice header (`tbl_charge_invoices`) contains the invoice number, date, and total amount.
    *   Individual services or products are added as line items in `tbl_charge_invoice_items`, each linked back to the main invoice via `charge_invoice_id`.
    *   The `payment_status` field on `tbl_charge_invoices` provides an at-a-glance view of whether the invoice is 'Unpaid', 'Partially Paid', or 'Paid'.

**3. `tbl_official_receipts` (Payments)**

*   **Purpose:** This table records all incoming payments from customers. An official receipt is the proof of payment.
*   **Process Flow:**
    *   When a payment is received, a user creates an official receipt, linking it to the customer who paid (`customer_id`).
    *   It stores the amount received, date, and payment method (e.g., 'Cash', 'Check').
    *   If the payment is by check, it can be linked to a bank in `tbl_banks`.

**4. `tbl_or_invoice` (The Junction Table)**

*   **Purpose:** This is a critical junction table that applies payments to invoices. It resolves the many-to-many relationship between `tbl_official_receipts` and `tbl_charge_invoices`.
*   **Process Flow:**
    *   After creating an official receipt, the user applies the received amount to one or more outstanding charge invoices.
    *   For each application, a record is created in `tbl_or_invoice`, storing the `or_id`, the `charge_invoice_id`, and the `applied_amount`.
    *   This design allows:
        *   A single payment to cover multiple invoices.
        *   A single invoice to be paid off by multiple payments (installments).

**5. `tbl_deliveries` & `tbl_invoice_deliveries` (Optional Flow)**

*   **Purpose:** Tracks the physical delivery of goods or documents related to an invoice.
*   **Process Flow:**
    *   A delivery record is created in `tbl_deliveries`.
    *   It is then linked to one or more charge invoices via the `tbl_invoice_deliveries` junction table.

**6. `tbl_users` & `tbl_activity_logs`**

*   **Purpose:** Manages system access and accountability.
*   **Process Flow:**
    *   `tbl_users` stores login credentials and roles.
    *   Whenever a user performs a key action (e.g., creates an invoice, records a payment), a record is automatically created in `tbl_activity_logs`, capturing who did what, and when.

**7. `tbl_app_setting`**

*   **Purpose:** Stores general configuration and branding for the application.
*   **Process Flow:**
    *   An admin user can update the application's name, logo, and contact details.
    *   This information is used globally across the application's UI.

---

✅ **Overall System Logic**

1.  **Onboard a Customer** (`tbl_customers`).
2.  **Create a Bill** (`tbl_charge_invoices` with items in `tbl_charge_invoice_items`).
3.  **Record a Payment** (`tbl_official_receipts`).
4.  **Apply the Payment** to the bill(s) (`tbl_or_invoice`).
5.  The system automatically updates the invoice's `payment_status`.
6.  All actions are logged for **auditing** (`tbl_activity_logs`).
